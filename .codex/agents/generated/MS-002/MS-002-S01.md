## Work and bounded decisions

1. Implement the plan's `custometry-install` CLI and `custometry-installation/v1` state in the proposed existing-tooling module plus a thin launcher. Package a standalone standard-library Python 3.12 toolkit; a consumer needs no repository imports, pip, uv or Node. Use existing trusted reader/extraction logic, not a second manifest/verifier implementation.
2. Implement install/status/resume/stop, protected directory ownership, stable random installation/Compose ID, exact engine-context binding, POSIX lock and atomic JSON writes. Parse configuration as data. Retain secrets and selected origin/port on retry; no global prune, unknown-directory adoption or removal of volumes.
3. Reuse the accepted MS-001 owner-local handoff and independent trusted inventory. Check platform/store/digests before import. Copy trusted input to a new private acquisition root; preserve the original toolkit and bundle bytes. Apply the known demo mount modes and 64-hex password rule when demo is explicitly selected.
4. Run preflight and one-shot migrations in the accepted order. Do not add domain tables or change `0009_notifications`. Artifact root is installation-owned, mounted at the existing API location. A real error/timeout leaves a diagnosable resumable state, never a success flag.
5. Prepare the owner-selected environment as part of this stage when executing under target-setup authority: explicit Python 3.12, mkcert, native UTM Ubuntu 24.04 ARM64, agreed VM/resource limits. Use ordinary official distributions and record exact versions/checksums; no source compilation or host-default replacement. Installing trust requires explicit administrator interaction; prepare the concrete operation first and reuse existing authorization. Missing OS authentication can pause that operation while independent installer work continues.
6. Produce the installation runbook additions and actual target/input record within this stage's report. S02 supplies TLS and stronger readiness; keep the unfinished end-to-end ready result unavailable. A not-yet-created VM is not a reason to reject S01 entry before doing this assigned setup work.
