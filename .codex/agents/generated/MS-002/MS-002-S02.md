## Work and bounded decisions

1. Extend S01's installed configuration with Nginx HTTPS on internal 8443, exact approved local or explicit LAN origin, protected read-only key/chain mounts and fixed Web upstream. Issuance and CA custody stay outside Edge. Use mkcert and existing OpenSSL as selected; no ACME service, custom PKI or renewed architecture choice.
2. Verify key/chain pairing, SAN/name, validity, trust and mounted permissions. Candidate rotation checks config before activation and trusted handshake afterwards; invalid candidates retain the last valid configuration. Never restore expired/revoked credentials or silently fall back to HTTP. Preserve the actual external Host/origin including its port through the proxy chain.
3. Generate a separate installation-only ingress configuration. Permit only the root entry, required same-origin assets, public `/docs/`, and GET health/version/installation status. Reject other product routes, API paths and methods; do not expose Identity bootstrap or generate a bootstrap token. C04 will replace this restriction with the protected account/workspace journey. Developer HTTP and existing feature routes retain their development boundary.
4. Strengthen readiness to check real control DB, exact supported `0009_notifications` head and writable canonical artifact root. Never migrate from a health request. Preserve existing health/version DTO shapes and add exactly the plan's `/installation/status` DTO, safe codes and no-store behavior; generate browser types through the existing contract mechanism.
5. Integrate installer status with real config/image/port/TLS inspection. A running process or one existing DB table is insufficient. Public responses exclude host paths, SQL and secrets; CORS does not become authorization. Edge retains separate adjacency and only it publishes ingress.
6. Update the runtime/API source documentation and retain positive/negative proof for S03/S04. No private Identity table reads, domain migrations, general operational dashboard or new service.
