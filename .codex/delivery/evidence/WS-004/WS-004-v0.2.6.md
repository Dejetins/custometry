# Requirements-complete analytical document composer

## Outcome and authority

The owner accepted the complete WS-004 v0.1.0 plan and C01–C11 on 2026-10-07,
then delegated sequential implementation, technical decomposition, milestone/pack
preparation, tests, repair and continuation without repeated milestone or stage
approval. [Authority evidence and preserved accepted source](../../../../../../.codex/delivery/evidence/WS-004/owner-continuation-2026-10-07.md)
record the exact decision. Version 0.2.0 incorporates that delegation; the eleven
outcomes remain unchanged. No Goal, publication, deployment, dependency installation
or data reset is authorized. Existing product holds remain in force.

Primary parent: [DIR-004](../direction.md), candidates C01/C02. Web work consumes
[DIR-005](../../DIR-005/direction.md); calculations remain with
[DIR-003](../../DIR-003/direction.md). This extends the composer; it does not
reopen historical MS-003/MS-004 or the retired UI packs. Existing
[WS-003](WS-003.md) owns its goal/shared-set decisions and outputs; consume them,
do not maintain a second execution status. The bounded W40 styling ticket is
historical evidence, not an execution ledger for this new scope.

A user can create several independently configured charts, tables and other
supported blocks; place chart/table side by side; build table-first, grid or
narrative pages; save/reopen, explore personally and publish authorized snapshots
without losing semantics, layout, access restrictions or history. The common
model serves Dashboard, Workbook/Report and Research profiles, not three forks.

Scope covers the complete requirement families listed in the
[clause matrix](WS-004-requirements.md), and UI-RPT-002, UI-DASH-003 and UI blueprint
8.5.3–8.5.4. These are composer-facing obligations, not a promise to implement
all unrelated platform requirements. An unavailable provider is an explicit
blocking dependency for its affected clause, never a mock completion.

## Preserved decisions and target boundaries

1. Presentation owns hierarchy, layout, bindings, drafts and immutable snapshots.
Analytics owns normalized analytical definitions, execution results and totals.
Semantic Model owns metric/filter/calendar meaning. Research owns findings;
Identity owns access. No cross-context private-table reads or client-side totals.
2. Reuse existing composition variants, repositories, ChartSpec/compiler, result
renderers and workspace components. Establish one canonical authoring model
with an explicit adapter for existing configured-report/v2; do not add a second
independent persistence truth or use browser localStorage as the document store.
3. Block identity is independent of selected card and screen position. Each block
has typed source/content references, local presentation and effective context.
Query identity excludes layout/density/selection-only changes; meaningful
parameter/filter/aggregation changes participate in result identity.
4. Preserve creator-only workbook definition writes (REPORT-018), personal view
semantics (REPORT-019), tenant/object/row/PII policy and immutable old snapshots.
No broadening permissions merely to make the editor easier to test.
5. Keep current visual tokens, compact cards, full values, metric selection,
checkboxes, table density/export and chart semantics. The compact toolbar is
an interim single-result composition, not a fixed constraint on the multi-block
editor: report-level controls stay global; selected-block controls are contextual.
6. The model must support arbitrary valid arrangements, not a special-case
"second chart" field or a hard-coded two-column mode. Bounded grid spans,
flow/narrative ordering, responsive reading order and resize constraints are
versioned presentation data. Do not offer unsupported freeform executable content.
7. No global Apply step is reintroduced for the present automatic calculation
flow. Builder commit/preflight, personal-view application and publication remain
distinct operations. Goal progress recomputation retains its accepted separate policy.
8. Forecast/scenario and other provider-dependent types need real versioned
provider output; preserve any existing holds. Supporting the block slot alone
cannot satisfy its analytical behavior. Universal XLSX remains the final new
functional increment under the existing direction sequence, not an early rewrite.

## Implementation detail by child

### C01 — evidence and compatibility seam

Inventory every matrix clause as code_observed, boundary_verified, documented_only
or unknown, with exact files/tests and provider owner. Read the actual running
checkout and active journals before choosing a new unit. Inspect all existing
composition versions and persisted report/view/snapshot readers and writers.
Define the new versioned authoring schema, typed layout constraints, stable IDs,
block union and capability negotiation. Resolve whether existing composition can
be evolved directly or needs a versioned envelope; do not assume v3 is available.
Specify error DTOs, revision checks, request identities, permission checks and
public ports before UI implementation. Required artifacts include valid/invalid
fixtures and old/new compatibility matrix. Resolve provider holds here.

### C02 — complete one vertical slice first

Implement additive persistence/API/schema/client paths. Hydrate existing reports
through a deterministic adapter into an equivalent single-result document while
preserving originals. Add one normalized builder with required subject/data
product → metric/grain → dimensions/period sequence. Add/duplicate/delete chart
and table blocks at explicit destinations; preserve stable IDs and bindings.
Block selection changes only local editor focus. Independent block loading,
error/retry and settings must not blank the entire document. Save/reopen actual
layout and definitions, not just current selection. Verify four different charts
and two tables, including chart/table sharing a compatible result without duplicate
compute. A standalone table requires no chart. Do not fake unavailable capabilities.

### C03 — full composition

Pages, optional chapters, nested ordered sections and typed layout; drag/drop plus
menu/keyboard equivalents, resize, move between sections, duplicate with fresh
IDs, delete with Undo, hide/lock/group, outline/tab overflow/search. Undo tracks
authoring operations and never undoes published history. Keep deterministic reading
order independent of visual grid position. Layout/density changes neither alter
analytical identity nor trigger compute. Profiles use shared components/contracts;
Research content lifecycle remains with its owner.

### C04 — correct analytical scope

Implement dimension-aware filters and explicit inheritance at document/chapter/
page/section/block; preserve security/system/metric constraints and linked-target
DAG. Show effective filters and overridden/locked origins. Store is a dimension,
not a synonym for all channels. Consume supported channel capabilities only.
Backend validation must enforce grain, null/ratio, relative windows, population,
calendar and comparison alignment. Include selected-card pair comparison and
per-block temporal override; keep global defaults explicit. Cancel/supersede stale
requests and do not paint an old response into a different block/context.

### C05 — reusable templates and exploration

Typed parameters with required/default/allowed values and explicit target mappings;
validated commit and pinned versions. Linked instance upgrade shows impact and
creates a draft; copy is independent with lineage. Define highlight versus filter,
drill-through and navigation separately. Show affected targets; reject cycles,
invalid destinations and permission failures. Back restores exact context/scroll/
focus. Saved personal values never mutate shared defaults or publications.

### C06 — analytical tables without shortcuts

Backend PivotSpec/PivotResult and metric-aware totals before shelf UI. Rows,
Columns, Measures, expand/collapse, transpose, sorting, top-N, formatting and
pinned headers consume typed results. Distinct and ratio totals are not sums or
averages of rendered cells. Preserve immature/missing/suppressed/zero states and
denominator provenance. Bounded projection/virtualization cannot truncate canonical
results. Metric trials and certified reusable measures follow MetricRegistry;
no report-local formula engine. Expose cancellation, cardinality preflight and
large-result fallbacks with honest capability status.

### C07 — complete block union

Implement heading, narrative, analyst_note, metric, metric_group, chart, table,
pivot, finding, conclusion, methodology, result_trust, forecast, scenario, quality,
metadata and Data Guide reference through typed adapters. Notes, annotations and
discussions are distinct; preserve semantic anchors and reviewed findings. Reject
executable HTML/raw SQL/chart-library options in saved documents. Unavailable
provider types remain explicit gaps with owner and proof dependency, never
invented results or permanently disabled substitutes claimed as completion.

### C08 — durable lifecycle and recovery

Separate Reader/Explorer/Author, personal/shared view, draft revision and published
version. Switching mode alone changes no results. Enforce creator checks server-side;
conflicts show reload/rebase choices without overwriting foreign edits. Publish one
immutable root/page manifest binding all included versions and author metadata.
Open viewers stay pinned until explicit update; refresh coalesces triggers, preserves
history, and advances current atomically. Surface waiting/failed/stale/last-good states.
Diff data/definition/parameters/policy independently from presentation; mixed/unknown
causes stay labeled. Revoke invalidates access regardless of cache.

### C09 — presentation and outputs

Reuse shared ChartSpec/compiler; local presentation defaults/overrides, legend,
series/grid/typography/palette only for supported capabilities. Focus preserves block
identity, full table, Escape and restoration. Export current block or exact document
snapshot with clear scope, full data and bounded overflow. Include branding, numeric
format, locale/timezone, accessible chart/table alternatives and supported PNG/SVG/
CSV paths. Integrate existing report-delivery preflight and lifecycle through its
owner; live send needs separate external-action authority. Plan final universal
XLSX after the required upstream direction outputs; test all channels' values and
cell states, not merely successful file creation.

### C10/C11 — prove and close

Run the scenario catalogue below across relevant roles/locales/layouts and failure
states. Measure bounded page/result loading, memory, concurrency and cache reuse
against the normative performance clauses; do not invent latency budgets. Fix each
in-scope reproducible bug, add a meaningful regression test, rerun the failed path
and affected adjacent paths. Record failures and unperformed tests honestly.
Screenshots prove layout only. Close only when clause-to-evidence coverage and
cross-child integration pass; separate owner acceptance from technical checks.

not silently flattened. No destructive backfill or production migration in this
planning authority. Operational execution requires its selected runbook.
