Контрольная точка G0 · правила визуального наследования

Каждый элемент с соответствующим образцом в пилоте наследует его правила полностью

Принятый пилот — обязательный источник визуальных правил. Если в нём есть соответствующий образец элемента, будущий интерфейс получает весь применимый набор его правил, а не выбранные отдельные свойства.

Какое решение требуется

Подтвердить обязательное полное наследование визуальных правил из ранее принятого пилота. Точное семантическое совпадение выбирает набор применимых правил; после этого нельзя взять только удобные цвета, размеры или скругления и проигнорировать остальные правила этого элемента.

Причина контрольной точки: прежнее решение закрепило визуальное направление v2. Текущая редакция впервые делает полное наследование проверяемым для каждого элемента и исправляет границу auth-маршрутов по действующему контракту 2.0.0.

Уже было принято

  • Визуальный язык пилота v2.
  • Его палитра, типографика, плотность, компоненты, состояния и responsive Web.
  • Пилот остаётся визуальным авторитетом программы.

Что фиксируется сейчас

  • Каждый элемент с образцом в пилоте наследует весь применимый набор правил.
  • Частичное наследование и эстетическое приближение запрещены.
  • Отклонение возможно только как узкое явно принятое исключение.

Что вы сейчас не принимаете

  • Внешний вид будущих экранов входа и восстановления.
  • Их конкретную композицию, тексты или данные.
  • Production-код, публикацию, deployment или mobile UI.

Как работает полное наследование

1. Определить элемент

Тип компонента, вариант, размер, состояние, slot и роль в shell сопоставляются с пилотом.

2. Получить весь набор

Для найденной идентичности собираются все применимые правила: не отдельная категория, а полный визуальный контракт элемента.

3. Проверить результат

Будущий элемент должен подтвердить весь набор. Пропущенное правило, подмена или приблизительное значение означают несоответствие.

Пример: если будущая кнопка совпала с вариантом кнопки пилота, она наследует одновременно типографику, цвета, размеры, внутренние отступы, границу, скругление, тень, иконку, состояния, focus, motion и responsive-поведение, которые пилот фиксирует для этого варианта.

Принятый пилот — источник правил

Отдельная техническая редакция добавляет только невидимые идентификаторы, чтобы правила можно было сопоставлять с элементами однозначно. Она не меняет визуальный язык пилота и не создаёт новый дизайн.

Что именно фиксирует стандарт

Правила извлечены из пилота, а не придуманы для будущих экранов. Точное семантическое совпадение определяет, какой полный набор относится к элементу. Оно не разрешает выбирать внутри этого набора только часть свойств.
