and explicitly requested its documentation, prompts and journal together.

part of the baseline delta, not already committed product behavior.

## Outcome and implementation overview

An analyst signs in with a prepared ordinary account, opens a pilot-derived
sales report, changes its period and store filter, inspects real calculated
values as a chart/table, saves the draft and reopens the same version/results.
The report is useful before full source-setup and administration screens exist.

The accepted scenario uses the existing Northwind Retail PostgreSQL
`demo` profile with six source tables: Customer, Product, Receipt, ReceiptItem,
Store and Calendar. Customer and Product inclusion is an explicit owner correction
(MS-003/DEC-04); ReceiptItem supplies the product-to-sale relationship. The first
report still uses three registered receipt metrics: net revenue, receipt count
and average receipt. Exact source, eligibility, currency, time and result
contracts are fixed in [MS-003](../../../milestones/MS-003/plan.md#implementation-decisions).
The first scenario is accepted under MS-003/DEC-01. Executors use its fixed
choices without repeating the initial owner question.

| Field | Definition |
|---|---|
| Included | Prepared isolated Identity/workspace/data path, governed intake of all six tables and their qualified relationships, versioned receipt metrics and result artifacts, bounded draft document persistence, pilot-derived report library/editor/preview, real save/reopen and failure behavior |
| Excluded | Self-service source wizard, full administration, publication/grant UI, separate-reader sharing, automatic/scheduled report refresh, free-form block/page builders, segmentation, email, XLSX, Forecasting, external delivery and production qualification |
| Reuse | Existing Identity services, PostgreSQL connector, DataPipelineRunner, artifacts/DQ/semantic publication, AnalyticsService, route registry, Web platform, accepted pilot, developer runtime, installer and bundle producer |
| Required change | Complete the missing product connections and bounded Presentation aggregate; do not introduce another report or calculation engine |
| Depth | No extra workstream level. One end-to-end milestone is the smallest coherent result; its sequential implementation stages do not need separate L2 documents |
