# WS-001. Installable platform and first administrator bootstrap

**Accepted L2, version 1.0.0, 2026-09-06.** The owner accepted the six decision
proposals, replaced the M3 target with a Mac M5 Max with 36 GB RAM, allowed Linux
testing in a VM on that Mac, and requested final English documentation and direct
main publication. The owner also selected simplicity, clarity, fitness for the
task and security as the engineering decision criteria.

This document owns the first block, MAP-001/SEQ-01 through SEQ-03. Its single parent
is [DIR-006](../direction.md) `1.2.0`; [DIR-001](../../DIR-001/direction.md)
and [DIR-005](../../DIR-005/direction.md), both `1.2.0`, contribute Identity and Web.
The global order remains [MAP-001](../../../project-map.md) `1.2.0`.
Acceptance covers this L2 contract and the five immediate outcomes below.
Unwritten L3 plans, prompt packs and implementation results are not accepted by it.

## Outcome and implementation overview

An administrator obtains a small versioned delivery, installs its prebuilt
containers, reaches the real Web application, creates the first account and
workspace through protected bootstrap, signs in and out, and retains identity,
configuration and data after restart. The application explains actual readiness
and the next workspace-setup action.

| Area | Accepted scope | Boundary |
|---|---|---|
| Target | Mac M5 Max / 36 GB host RAM; separate Linux VM installation tests on the same Mac | Record guest OS/architecture, engine/hypervisor versions, resource allocation and network mode before proof. No generic Linux, x86_64 or production claim follows from the VM |
| Resources | Preserve the normal demo ceilings of 6 GiB RAM and 25 GiB owned data; CPU-only and configured caps | Host capacity is not an application allocation or workload/SLO promise. Run target tests sequentially |
| Access | Local by default; explicit LAN configuration with HTTPS and browser proof from another computer | No hidden wildcard bind, credentialed wildcard CORS or public-Internet exposure. Production SEC-018 qualification remains separate |
| Installation experience | Administrator preinstalls the supported container engine, runs the launcher and supplies installation directory/access inputs; installer owns preflight, configuration/secrets, downloads, migrations/readiness and actual URL | No manual YAML/SQL editing, source build, native graphical installer or automatic host-engine installation is required for the normal path |
| Delivery | Small versioned launcher/configuration and compatible immutable images with inventory, provenance/signature/checksum verification and declared capabilities | Reuse the current origin and tooling where applicable; an image candidate is not an accepted installable delivery |
| Bootstrap | One first account combines installation administration and explicitly disclosed initial roles in the first workspace; show those grants before completion | Identity defines the initial policy needed to establish role delegation. No implicit other-workspace or PII access; normal role ceilings resume after bootstrap |
| Web | Bootstrap, sign-in/logout, safe errors, independent language/format-locale/timezone, persistent initial checklist and clear next action | Preserve the target pilot and ADR-0007; full invitations/member administration remains SEQ-04 and data onboarding follows later |
| State | New installation-owned storage; no required migration of experimental data; preserve foreign installations | Persist identity, secrets, versions and paths across retry/restart. Do not reset data to make a check pass |
| Recovery | Failed installation/migration/readiness, restart and documented host-assisted first-admin recovery | Full coherent data/report backup, schedules and product update/restore cycle remain SEQ-12; storage and compatibility prerequisites are designed here |

The bundle grows as later milestones add working capabilities. Every declared
capability includes its real dependencies; unavailable services cannot be green.
Existing analytics/data code is neither certified nor rewritten by this block.
Working demonstrations use the normal data path once its later providers exist;
this block does not invent a second ingestion engine or fabricate ready data.

Additional workstream nesting: `not_applicable`. Keep the standard L2-to-L3 form.
A simpler arrangement is preferred unless a demonstrated contract or acceptance
boundary requires a split. The owner decides any material regrouping and agent
organization; no parallel dispatch is selected.

Documentation changes do not modify application API or persisted records.
The policy changes above are accepted target changes, not observed implementation.
TLS issuance/renewal stays outside Edge, with no certificate-acquisition egress.
Preflight verifies protected file references, key/chain match, name/trust/validity
and approved origin. Rotation validates before activation and checks the handshake;
invalid candidates keep the previous valid configuration. Expired/compromised
credentials require forward repair; HTTP and revoked keys are never rollback paths.
Never put credentials in Git, URLs, images, environment values or logs.

requirement; reuse existing contracts and tooling; add a component only for a
demonstrated missing boundary. Do not design a generic framework for hypothetical
installers, clouds, registries, remote workers or future forecasting.
