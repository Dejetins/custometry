# WS-001. Installable platform and first administrator bootstrap

The owner selected **delivery, installation and bootstrap** as the first block to
develop in depth on 2026-09-06. Selection is accepted in
[MAP-001](../../../project-map.md#accepted-delivery-sequence) `1.1.0` and
[DIR-006](../direction.md) `1.1.0`. This new L2 document is a `0.1.0` draft:
its candidate children, detailed boundaries and proof allocation still require
owner review. The next work is to develop this document, then create the selected
L3 milestone plan. No milestone, prompt pack or journal has been initialized.

## Outcome and implementation overview

An installation administrator obtains a versioned, prebuilt Custometry delivery,
installs it on the supported target, reaches its real Web UI, creates the first
administrator and workspace, signs in, and retains that state after a controlled
restart. The UI explains the next workspace-setup action and the actual readiness
of the delivered capabilities.

The workstream covers MAP-001/SEQ-01 through SEQ-03. The whole first operational
outcome continues through members, sources, usable data, analytics, report authoring,
publication/access, a separate reader, refresh and recovery. WS-001 alone does not
complete that larger outcome or any external product release label.

| Area | Included in this first workstream | Boundary / later owner |
|---|---|---|
| Delivery | Versioned launcher/configuration, compatible immutable images, dependency/assets inventory, provenance/checksums, installation instructions and an explicit delivered-capability list | The accepted release source and publication procedure must be resolved before publication; this document grants no external write |
| Installation | Target preflight, deployment identity, explicit ingress/origin configuration, protected local secrets, persistent stores, separate migrations, start/readiness and diagnosable failure | Preserve the accepted single-server topology; additional platforms or network exposure require their own proof |
| Initial Web access | Real bootstrap/sign-in routes, safe errors, first workspace context, locale/timezone choices and resumable initial setup | Full staff invitations, role-management UI and complete local-auth lifecycle are allocated to SEQ-04; first-administrator security cannot be deferred |
| Identity | One-time deployment bootstrap, first administrator/workspace, explicit membership/grants, session creation/logout and irreversible bootstrap closure | Identity remains the domain owner; installation authority never silently grants access to unrelated workspace content |
| Persistence and recovery | Retain installed identity/configuration after restart; safe retry of failed installation; define migration compatibility and host-assisted bootstrap recovery; prove the scoped recovery behavior | Whole-product backup/restore, automated schedules and exact report recovery remain SEQ-12; their storage/version prerequisites are considered now |
| Handoff | A repeatable installed baseline, version/readiness visibility, relevant admin instructions and a clear transition to workspace setup | Sources, data preparation, computation, reports and reader access belong to their later sequence rows |

The delivery grows as later milestones add capabilities. The first bundle must
contain every dependency of its declared scope and must not mark absent components
healthy. It does not wait for all future analytics, workers or report modules to
be implemented. Existing functioning components are reused after applicability is
checked; the workstream is not a from-scratch rewrite.

Additional workstream nesting: `not_applicable` at this draft. Use the standard
L2-to-L3 structure unless investigation shows a distinct scope requiring another
workstream level and the owner accepts that reason.
