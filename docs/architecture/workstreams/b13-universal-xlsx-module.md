# B13 Universal XLSX — module definition

## Purpose and sequencing

B13 is deliberately the final feature workstream. It assembles any accepted
`ReportSnapshot` into one entity-aware `.xlsx` workbook with stable data,
charts, tables, metadata, lineage, filters, and trust information. It begins
only after B10 reporting contracts, B11 extensibility/operational contracts,
and B12 production hardening are accepted.

B13 does not redefine report semantics, calculate analytics, or export to
external databases.

## Ubiquitous language

| Term | Meaning |
|---|---|
| Workbook assembly spec | Versioned mapping from ReportSnapshot blocks to workbook entities |
| Entity block | Typed KPI, table, chart, timeline, text, guide, or metadata block |
| Data sheet | Normalized source data for one or more workbook visual entities |
| Presentation sheet | User-facing composed workbook page |
| Native chart | Supported Excel chart built from workbook ranges |
| Raster fallback | Deterministic PNG from the shared renderer when native parity is unavailable |
| Workbook manifest | Snapshot identity, block mapping, sheets, ranges, charts, hashes, warnings, and versions |
| Split plan | Deterministic row/column/sheet partition without loss or duplication |

## Domain model and invariants

- Input is an immutable, permission-checked `ReportSnapshot`; B13 never queries
  mutable source data independently.
- Every snapshot block maps through a versioned entity contract.
- Web/email/XLSX use the same resolved source artifacts, filters, metric and
  comparison versions, schemas, units, lineage, and golden totals.
- Workbook rows are never lost or duplicated across Excel limits.
- Sheet names are deterministic, valid, unique, localized safely, and collision
  resistant.
- Formula-like text is neutralized without corrupting genuine typed formulas
  explicitly generated by the assembler.
- Native charts are used only when semantic parity is proven; otherwise the
  same deterministic PNG fallback used by reporting is embedded.
- Chart/table/timeline data remains inspectable and linked to its data ranges.
- Workbook metadata records snapshot, filters, `vs LY`, Result Trust, lineage,
  generator/compiler/renderer versions, and warnings.
- Sensitive fields obey the same permission/export/redaction policy as the
  snapshot.
- Memory, temp disk, rows, columns, images, styles, and workbook size are
  bounded with safe failure.

## Commands and ports

`AssembleWorkbook(snapshot_id, export_policy)` validates input, plans sheets,
writes entity data, creates native/raster visual blocks, validates OOXML, stores
an immutable artifact, and returns run/status identity. Cancellation removes
uncommitted temp output. Idempotent retries reuse only identical request and
content identities.

Outbound ports consume B10 ReportSnapshot/block schemas, B06 ChartSpec/static
rendering, B08/B09 typed block contracts, B04 execution/artifacts/progress, B03
permissions/audit, and approved workbook/OOXML libraries. No spreadsheet
library leaks into domain/application policy.

## Artifact and security boundary

The workbook manifest includes source hashes, sheet/range mappings, output
hash, byte size, library/compiler versions, warnings, and sanitization counts.
Temporary files use bounded stage-owned storage and are cleaned on success,
failure, and cancellation.

External links, macros, remote data connections, executable objects, and
formula injection are forbidden. Workbook openability is checked with
OOXML-aware validation and at least one supported spreadsheet application
boundary where available.

## UI and acceptance

The export flow exposes scope, format, estimated size, permissions, progress,
ETA, cancellation, warnings, download, expiry, and audit identity. Large or
unsupported blocks explain fallback/split behavior before or after generation
without silent truncation.

B13 hard-depends on B10, B11, and B12; B06/B08/B09 are soft schema providers.
It closes `v1_feature_freeze` at S06. Acceptance requires cross-render golden
totals, Excel-boundary split tests, formula-injection tests, sheet collision,
native/raster chart parity, memory/temp bounds, cancellation/cleanup, real
workbook openability, browser flow, cold review, and all routed requirements
reconciled.
